入口仍为 main.py，第一版目录不变。单次识别、选区配置和交互式测试工具均保留。
已运行本地 OCR、模拟流程及窗口预览回归，尚未执行真实 AI 请求或页面点击。

## 启动与操作

CMD：

```cmd
cd /d D:\Users\ranshen1\Codex\deepseek_answer\DeepSeekAssistant-v2
.\.venv\Scripts\python.exe main.py
```

如果第二版缺少依赖，可自行安装完整依赖组：

```cmd
.\.venv\Scripts\python.exe -m pip install -r requirements-auto.txt -i https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple
```

1. 关闭独立测试面板，保留答题页面；点击助手的“设置题目区域”。
2. 框入顶部题型、完整题干、全部选项和底部提交/下一题按钮，限一个显示器。
   旧选区如果只有题干和选项，必须重选。选区保存至现有 config.yaml。
3. 现有 config.yaml 的 api_key、base_url、model、timeout 继续使用，无需另写密钥。
4. 点击“开始自动答题”，这会调用配置的图片理解 API，并在状态核对通过后真实选择、提交和翻题。
5. 界面显示当前题型、AI 答案/解析、执行阶段、本次确认提交数及跳过已提交数。
6. 点击停止或按 Esc。截图与点击时面板隐藏，此时可使用全局 Esc。
   API 请求不能强制中断；停止信号会立即记录，返回后丢弃答案，任务结束前不发送后续点击。

运行时请勿移动浏览器、切题、滚动、修改缩放或用其它窗口遮挡答题区域。
不读取侧栏题号或完成数量；本次计数只描述本次进程已观察到的结果，不是 50 题总进度。

## 自动流程

截图本地识别 → 检查是否已提交 → AI 返回结构化答案 → 重新确认题目 →
按本地坐标选择 → 确认选中 → 确认蓝色提交可用 → 提交一次 → 确认已提交 →
下一题 → 确认题目切换 → 循环。

已提交的题跳过 API 和选项点击。按约定，“已提交且下一题灰色禁用”连续两次观察一致即结束。
下一题未知、提交未知、题型不支持、选项漏检、AI 答案不确定/格式错误、网络失败均暂停。
不支持方形多选框，本版自动模式只接受 A/B/C/D 四项单选及 √/× 判断。

提交后自动翻题：不补点下一题，确认新页面观察稳定后继续；旧题的提交结果未单独确认，
不会将它计入“本次确认提交”。没有确认提交且也没有稳定切题则暂停，不重复提交。
未答题时提交灰色不阻止调用 DeepSeek，仍先选中其答案。
确认选中后，如提交按钮尚未更新为可用，最多观察六次等待页面更新；
真正提交前再核对一次选中标签必须与 DeepSeek 答案一致。
持续不可提交只会暂停，不能作为作答完成条件，也不会重复点击选项或提交。
本进程内尚未确认的提交保留待确认锁，普通停止再开始不清除；成功确认后转入独立成功记录。
记录不跨重启保存，明确点击“新一轮答题（清除旧记录）”才会清除本轮记录并开始新一轮。
AI 返回后的题目标识与实时页面不符时暂停，避免旧答案用于新题。

## AI 接口

原 core/deepseek.py 的 analyze_image 供单次识别，仍返回题目/答案/解析文本。
新增 analyze_answer 供自动流程，发送内存 PNG，严格校验字段：

```json
{"question_type":"single","answer":["B"],"explanation":"简短解析","uncertain":false}
```

判断题的 answer 为 ["true"] 或 ["false"]。JSON 字段、类型、答案数量、题型与标签必须匹配。
不从自由文本中搜字母、不执行页面或模型给出的命令、不使用模型给出的坐标。
模型返回解析按纯文本显示。API 密钥不写入状态或日志。
沿用当前配置的模型与接口，图片和请求格式是否兼容尚未调用验证；若 HTTP 400/404
或返回格式不符，会显示原因并暂停，不会静默改模型或切换提供商。

## 模块

- ui/main_window.py：开始/停止按钮、阶段、答案和计数。
- ui/controller.py：任务互斥、配置、全局 Esc、截图前隐藏窗口的握手。
- core/auto_worker.py：后台 OCR、AI 请求、停止事件、窗口显示/隐藏请求。
- core/auto_flow.py：一次选择、提交、翻题以及完成判定的连续状态流程。
- core/answer_schema.py：只接受约定的答案数据，拒绝额外字段与模糊答案。
- vision/：继续负责本地定位、状态识别、坐标转换、Windows 单击和逐步验证。

单次识别和自动任务不会同时运行。等待 AI 时助手可显示，下一次截图前先隐藏并等待界面确认。
正常运行时截图保留在内存；异常暂停时保存最近四次截图及识别报告至 outputs/auto_debug_日期时间_编号。
failure.json 记录暂停原因、阶段及物理选区，逐张 report.json 包含题目标识原文和选项，
不保存 API 配置、密钥或请求体。主动停止不写诊断快照。已有单次识别的 screenshots 行为不变。

## 题目标识误判诊断与修复

已用用户提供的 Runway 题目截图复现：图片左侧增加 2 像素白边后，OCR 将标题的
28.单选题识别为128.单选题，题干与选项没变，但旧版包含标题的 SHA256 标识变化，导致拒绝点击。
这证明旧标识存在误判；原故障发生时未保存前后图片，无法追溯确认当次具体文字差异。

vision/question_identity.py 现使用题型、题干和实际选项文字，不使用题号/分值/装饰条。
Unicode 规范化、忽略空白与 OCR 分行；不使用宽松相似度，不忽略题干和选项的实际内容变化。
JSON 的 question_identity 保留参与比较的数据，question_signature 是它的摘要。
缺失题干时标识为空并暂停，不能仅靠题号或标题确认题目。

tools/diagnose_question.py 可 --capture 使用保存选区连续采图，或 --images 输入多张现有原图，
保存 OCR、标注图、comparison.json、question_diff.txt；不会调用 API 或点击鼠标。
诊断同时记录旧版含标题标识与新标识，方便比较修复前后的行为。

### 提交锁的显式恢复

主助手新增“重新检查并重试本题”。当提交已发送但未确认（如安全核验中断）时，
普通开始仍拒绝重复提交。用户先手动完成页面核验，确认没有弹窗，再点击恢复按钮。
后台连续两次检查待恢复题的标识、未提交状态、完整选项、唯一已选中项及蓝色提交按钮；
通过后重新请求 AI 并确认其答案选中，允许本题尝试提交一次，然后继续正常自动流程。
若本题已提交则不重发，直接检查下一题；当前题变了或状态不明确则拒绝恢复。

恢复操作不批量清锁，不自动处理核验。成功后移除本题待确认锁并保留成功记录，
恢复失败后普通开始仍受锁保护；
再次恢复需要用户重新点击该按钮。停止与 Esc 检查仍生效。
只有本进程存在待恢复记录且任务空闲时恢复按钮才可用，程序重启不保留内存锁。
tests.test_auto_retry 使用模拟 API/鼠标及真实锁故障图片验证恢复条件，未提交真实页面。

### 成功记录与待确认锁分离

submit_attempts 仅存待确认提交，confirmed_submissions 存已确认成功的题目，两者独立。
点击提交先加入待确认；读到同题“已提交”即移入成功记录，解除待确认锁。
普通开始保留记录；成功历史本身不阻止对当前明确未提交的题作答。
自动翻题但旧题提交未单独确认时仍保留旧题待确认锁，不擅自视作成功。

“新一轮答题（清除旧记录）”用于已切换另一套题或重新作答的情况。
只在空闲时可用，配置校验通过后清除本地待确认和成功记录、重置恢复入口、生成新 session_id 并开始。
不会重置网页，也不会自动完成网页核验；仅清本地记录不表示网页已重开一轮。
新旧轮次通过 session_id、pending_submissions、confirmed_submissions 写入失败诊断，方便追溯。
正常换题清空上一题 AI 答案，防止当前题暂停时仍显示旧答案。
